## 框架定义

CO-STAR 把一条结构化 prompt 拆成六个要素：

| 字母 | 要素 | 英文 | 回答的问题 |
|---|---|---|---|
| **C** | 背景 | Context | 任务发生的背景信息是什么？ |
| **O** | 目标 | Objective | 你要模型输出什么？ |
| **S** | 风格 | Style | 按什么写作风格来写？ |
| **T** | 语调 | Tone | 输出的情感态度是什么？ |
| **A** | 受众 | Audience | 内容是写给谁看的？ |
| **R** | 响应 | Response | 输出格式是什么？ |

## 各要素说明

**C · Context（背景）**
提供任务所需的背景信息：你是什么角色、公司/产品情况、此前发生了什么、模型需要哪些领域知识。背景是其余所有要素的地基——同一句话在不同背景下含义完全不同。

**O · Objective（目标）**
明确说明你要模型做什么、期望输出什么效果。要具体到"意图"层面：不是"回答用户问题"，而是"帮用户在最短时间内解决问题"。

**S · Style（风格）**
指定写作风格，让模型模仿某个具体参照物：鲁迅风格、麦肯锡顾问风格、Apple 文案风格。风格是区分"泛泛输出"与"特定输出"的关键。

**T · Tone（语调）**
设定情感与态度：正式/随意、幽默/严肃、说服性/激励性。语调决定内容"读起来的感觉"。

**A · Audience（受众）**
说明输出是给谁看的：受众的身份、专业水平、关注点。受众越具体，模型的用词、举例、深度校准越准。

**R · Response（响应格式）**
指定输出格式：纯文本 / Markdown / JSON / 表格；长度；结构（是否编号、是否含小标题）。工程场景中这一项直接决定输出能否被程序消费。

## 完整示例（译自原作）

> **# 背景（CONTEXT）#** 我想推广公司的新产品。公司名为 Alpha，新产品名为 Beta，是一款新型超快速吹风机。
> **# 目标（OBJECTIVE）#** 帮我创建一条 Facebook 帖子，目的是吸引人们点击产品链接购买。
> **# 风格（STYLE）#** 参照戴森等成功公司推广类似产品时的文案风格。
> **# 语调（TONE）#** 说服性。
> **# 受众（AUDIENCE）#** 我们公司在 Facebook 上的主要受众是老年人，请针对该群体选择护发产品时的典型关注点来定制帖子。
> **# 响应（RESPONSE）#** 保持 Facebook 帖子简洁而深具影响力。

## 配套技巧：分隔符

CO-STAR 原文配套建议用**分隔符**把各要素隔开：基础用 `###`，配 HTML/XML 标签（如 `<example>` 包示例）。分隔符让模型无歧义地区分"指令""背景""数据"各部分，是结构化 prompt 的通用基建。

## 适用边界

- **适合**：输出质量取决于风格、语调、受众、格式的任务——内容创作、营销文案、面向特定人群的沟通、系统提示词设计。
- **不必用**：简单事实问答，一条朴素提示即可；框架是指导而非模板，不适用的要素可以跳过。
- **与 CoT 的关系**：CO-STAR 管"输出成什么样"，CoT 管"怎么思考"，两者可以叠加使用。
