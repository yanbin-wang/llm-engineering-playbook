# Anthropic 官方提示工程最佳实践（中文版）

[← 返回决策入口](../README.md)

> 来源：Anthropic 官方文档 *Prompt engineering overview*（platform.claude.com/docs → Build with Claude → Prompt engineering）
> 本篇为官方技巧清单的中文编译，保留原文结构，未做汇总改写。

## 1. Be clear and direct（清晰直接）

像对待一个聪明但刚入职、缺乏上下文的新人一样写指令：

- 把任务、约束、期望结果在一句话里说全，不写"帮我看看"式模糊指令
- 想要什么格式就说什么格式（"输出 JSON，含 summary 和 risk_level 两个键"）
- 把上下文/文档放在指令**前**，用标记隔开
- 步骤有顺序要求时用编号列表逐条写
- 说不清"什么是好输出"时，描述"什么算坏输出"

## 2. Use examples (multishot prompting)（用示例）

示例是引导输出格式、语调、结构**最可靠**的方式：

- 3~5 个示例效果最好（few-shot / multishot）
- 示例要**相关**（贴近真实场景）、**多样**（覆盖边界情况）、**结构化**（用标签包裹，与指令区分）
- 示例比长篇描述指令更省 token、更难被误解

## 3. Let Claude think (chain of thought)（让模型思考）

复杂任务允许模型先写中间推理步骤再给答案：

- 对数学、逻辑、多步分析类任务显著提升表现
- 引导语："先在 \<thinking\> 标签内逐步思考，再在 \<answer\> 标签内给出最终答案"
- 思考过程会占输出 token，简单任务不要滥用

## 4. Use XML tags（用 XML 标签结构化）

当 prompt 混合了指令、背景、示例、待处理数据时，用 XML 标签包裹各类内容：

- 如 `<instructions>`、`<context>`、`<example>`、`<document>`
- 标签名称一致且描述性强；有层级时用嵌套（多份文档包在 `<documents>` 内）
- 官方明确推荐此法，它让模型无歧义地解析各部分边界

## 5. Give Claude a role（给角色）

在 system prompt 中设定角色，把模型行为聚焦到使用场景：

- "你是一名资深数据工程师"——角色约束输出视角、措辞水平和知识层次
- 角色放在 system prompt 而非正文，对行为的约束力更强

## 6. Prefill the response（预填充响应）

在 assistant 侧预置回复的开头几个词：

- 可以强制跳过客套前导、直接进入格式（预填 `{` 强制 JSON 开头）
- 也可用于控制输出起点、禁用特定开头方式

## 7. Chain prompts（链式提示）

把复杂任务拆成多次调用，前一步输出作为后一步输入：

- 每一步任务更窄、成功率更高，且可逐步检查
- 典型拆法：先"提取要点"再"按要点写作"；先"分类"再"按类回答"
- 适用于：任务有明确子结构、单次调用要同时做太多事、需要中间结果可审计

## 8. Long context tips（长上下文技巧）

把长文档放进 prompt 时：

- 文档放 prompt 顶部（开头），指令放底部——官方实测此顺序表现最好
- 要求引用来源段落（"答案必须引用文档中的具体段落"）可显著抑制胡编
- 多文档分别用标签包裹并编号，问答时要求先引用编号再作答

## 官方建议的通用工作流

1. 先用最朴素的一条提示跑通，建立基线
2. 按"清晰直接 → 示例 → XML 标签 → 角色"逐项加强，每次只改一处
3. 用官方 Prompt Improver / 评测集对比改前改后
4. 复杂任务拆链式调用；仍不够才考虑微调（见[路线 C](../README.md#路线-c-微调)）
